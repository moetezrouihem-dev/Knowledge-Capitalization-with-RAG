# QLoRA Fine-tuning — SFM Technologies Assistant

Fine-tunes a small language model (Qwen2.5-3B-Instruct) on SFM Technologies internal files as a complement to the RAG pipeline already in
production.

## Files in this folder

| File | What it does |
|---|---|
| `extract_corpus.py` | Extracts clean text from the 52 real source documents into a `corpus_text/` folder. Includes a custom parser for the JS-embedded document registry hidden inside the SMQ HTML dashboard. |
| `gen_template_qa.py` | Generates Q&A pairs **deterministically** from structured data , each answer is copied directly from real fields, so there's no hallucination risk. Contains one illustrative example only; the rest is omitted for confidentiality. |
| `gen_manual_qa.py` | Q&A pairs hand-written from reading the narrative procedure documents, each checked against the source text before being written. Contains one illustrative example only; the rest is omitted for confidentiality. |
| `merge_and_split.py` | Merges the Q&A batches, removes duplicate questions, and splits 90/10 into `train.jsonl`/`val.jsonl`. |
| `finetune_sfm_qlora.ipynb` | **The actual training pipeline** — ready to run in Google Colab. Loads the base model, applies LoRA, trains, exports (LoRA adapter / merged model / GGUF). This is the notebook that produced the real fine-tuned model. |
| `train_local.py` | to run training locally on a Windows machine ( my own RTX 4050). 
| `eval_compare.py` | Compares the **base** model against the **fine-tuned** model on the validation set, on measurable metrics (citation accuracy, keyword recall) .|

## What's not included, and why

`train.jsonl`, `val.jsonl`, and the full versions of the `gen_*.py` scripts are
**not included** in this repository. They contain excerpts of SFM Technologies'
real internal documentation, confidential company data that shouldn't be
published, regardless of repository visibility.

What's shown here is the real methodology and real code structure, with company
specifics redacted or omitted. In short:

- **246 pairs** were generated by template from structured registers;
  each answer copied directly from real fields.
- **36 pairs** were hand-written from narrative procedure documents, verified
  against the extracted source text.
- All 282 pairs were merged, deduplicated, and split into `train.jsonl` (254
  examples) / `val.jsonl` (28 examples).
- All answers follow the same `[Source: file]` citation format as `rag_chain.py`,
  so the fine-tuned model mirrors the RAG system's output style.

## How to run it

1. Open `finetune_sfm_qlora.ipynb` in Google Colab .
2. Enable a GPU: Runtime → Change runtime type → T4 GPU .
3. Run the cells in order. When prompted, upload your own `train.jsonl`/`val.jsonl`.
4. Training takes ~15-25 minutes on a free T4 for ~280 examples over 3 epochs.
5. Three exports are produced: LoRA adapter, merged 16-bit model, and GGUF
   (for local use with Ollama).
6. Run `eval_compare.py` (paste into a new Colab cell) to get the base-vs-fine-tuned
   comparison table.

## Conceptual notes

- **QLoRA** = 4-bit quantization of the base model (memory savings) + LoRA
  (small trainable low-rank adapters layered on top of frozen base weights).
- `r=16`: rank of the LoRA matrices , enough capacity for a few hundred examples
  without overfitting.
- Watch `eval_loss` vs `train_loss` during training: if `eval_loss` starts rising
  while `train_loss` keeps falling, that's overfitting — reduce epochs or rank.
